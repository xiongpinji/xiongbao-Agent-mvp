# 熊宝-Agent 项目资产版本合同（PS-06B-1）

状态：2026-09-25 经 GLM-5.3 独立只读设计审查为修订后 GO；同项目跨节点版本隔离与任务分享权限边界已修入实施合同。本片承接已推送的 023A 私有项目资产，不预设 WorkBuddy 的服务端实现。用户本机 WorkBuddy 5.6.2 项目资产文件右键菜单有“版本管理”；弹窗左侧按版次和时间列出历史、标记当前版，右侧预览选中版。现场仅有第一版，尚未实测新版本上传、恢复和删除。熊宝先交付可验证的版本数据、成员权限与管理交互；安全预览和删除回收分别另片验收。

## 边界和不变量

- 版本属于同一个项目中的一个文件节点。023 表 `project_asset_versions` 已有不可变 `object_key`、大小、摘要、上传人、时间和 `is_current` 部分唯一索引；本片不复用用户输入的文件名构造路径，不覆盖旧对象字节。当前版本切换只改指针，旧版仍可按明确版次下载。
- 当前项目成员 owner/admin/member 均可查看版本与下载；当前项目成员可上传新版本或恢复旧版，与 023A 上传权限一致。非成员、被移除者、跨项目节点/版本、同项目但不属于路径节点的版本、目录节点、未知 ID 一律 404；所有版本 SQL 必须以 `(project_id,node_id,version_id)` 三元组过滤，或等价地断言版本的 `node_id` 与路径节点一致。复用既有仅按 `(project_id,version_id)` 查询的 `_VERSION_SELECT` 时必须补此检查。已归档项目允许查看/下载，禁止上传/恢复并返回 403。每次请求重复服务端授权，客户端持有节点 ID、版本 ID、旧链接或已打开弹窗均不构成授权。024 任务卡片授权与 025 正文授权不构成任何资产权限；版本接口只读取当前 `project_members` 行，不复用任务可见性/分享判定。未来若将任务授权扩展到非项目成员，须先修订本合同。
- 旧版下载固定 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`，从 023A 的私有存储 `open_download` 读取，拒绝符号链接与目录替换。不得返回 `object_key`、绝对路径、临时路径、凭据或可长期访问的公开 URL。已经开始传输的流不因后续撤权中断；撤权后的新请求必须 404。
- 一个文件节点在任何已提交状态恰有一个当前版本。上传新版本与恢复旧版在同一文件上串行：单个数据库事务先锁调用者成员行（PostgreSQL `FOR SHARE`），再锁目标文件节点行（PostgreSQL `FOR UPDATE`；SQLite 整个事务使用 `BEGIN IMMEDIATE`），核查项目未归档和同项目文件；上传与恢复均先将旧 `is_current` 置 0，再插入/置位目标版本，更新节点时间后提交。两个操作的锁序一致，不依赖前端避免竞态。失败时原当前版不变。
- 新版本遵循 023A 的发布顺序：分块写私有临时文件并算摘要/大小 → 原子发布服务端生成的最终对象 → 上述数据库事务插入新版本并切换当前版 → 成功响应。事务失败只清理本次新对象，不删除任何既有版本；进程崩溃产生的未引用对象仍由受限孤儿回收处理。上传文件名不重命名现有节点，页面明确显示目标文件名；MIME 以现有节点名保守推断，浏览器声明只作提示。
- 恢复已存在版本不复制字节、不新建版本。成员与非归档写权限检查先于幂等判定，因此归档项目即使恢复已为当前的版本也返回 403。恢复当前版本是无副作用的幂等成功；恢复非当前版本前检查私有对象存在且为安全普通文件，检查时缺失即统一 404，不得已知对象缺失还将其设为当前版。检查后的外部磁盘篡改仍可能发生，需以下载探针发现，而不声称数据库能保证物理文件永不损坏。
- 023A 的容量指标当前只计当前版本；本片维持该既有语义并在页面标为“当前文件用量”。历史版本实际物理占用和项目配额另在 PS-06B-2 设计与实施，不能虚称 10 GB 配额或把历史文件计入已执行配额。新版本上传与恢复不写 `project_events`，逐操作持久审计另归 PS-09。本片不做删除/回收、移动/重命名、任务引用、外部预览服务、版本差异比较、批量恢复或目录版本。

## HTTP 合同

| 路由 | 响应与行为 | 失败 |
| --- | --- | --- |
| `GET /api/projects/{project_id}/assets/{node_id}/versions?limit=50&offset=0` | `{items,total,limit,offset,has_more}`，默认 `limit=50`、范围 1–100，`offset≥0`；按 `(created_at DESC,version_id DESC)` 全序；每项 `{version_id,size_bytes,sha256,media_type,uploaded_by,created_at,is_current}`，`uploaded_by` 为可空的不透明用户 ID，页面无可用用户名时显示占位。 | 非成员/目录/跨项目 404；非法分页 422 |
| `POST /api/projects/{project_id}/assets/{node_id}/versions` | multipart `file`；201，返回 023A 安全节点 DTO `{node_id,parent_node_id,kind,name,size_bytes,media_type,created_at,updated_at}` 加 `version:{version_id,size_bytes,sha256,media_type}`。服务端沿用 023A 单文件上限、流式写入和原子发布。 | 非成员/节点/目录 404；归档 403；超限 413；发布或事务失败无可见半版本 |
| `POST /api/projects/{project_id}/assets/{node_id}/versions/{version_id}/restore` | 200，返回与新版本上传相同的安全节点 DTO 加 `version` 摘要；版本已是当前时仍返回 200，不能产生新对象或新版本。 | 非成员/节点/同项目错误节点版本/对象缺失 404；归档 403 |
| `GET /api/projects/{project_id}/assets/{node_id}/versions/{version_id}/download` | 该历史版本的私有附件流；下载文件名使用当前节点名。 | 非成员、撤权、跨项目、目录、未知版本或对象缺失 404 |

所有路径沿用 `/api/projects` 现有登录、错误封套和 OpenAPI 文档方式；静态路由顺序不得被 `/{node_id}` 吞没。文件名字节不作为版本上传路由的节点选择依据。读请求在一次数据库事务内锁成员并读取目标节点/版本，避免撤权后沿用旧授权快照；版本列表的计数和分页数据在同一授权事务内读取。PostgreSQL 默认隔离级别下并发插入可能使两次查询的快照不同，前端须允许刷新，不能把 `total` 当授权依据。

## Dashboard 交互

- 文件行右键或更多菜单新增“版本管理”。弹窗保持 WorkBuddy 观察到的宽版式：左栏版次/时间/当前标记，右栏显示选中版的安全元数据、下载入口及“恢复为当前版”。当前版禁用恢复按钮。首版显示“第 1 版”；本片版次仅由固定数据集的排序/计数推得，版本 ID 才是操作标识；并发同秒上传可能使显示版次重排，不得用版次做下载或恢复依据。对不能安全预览的类型显示明确占位，不嵌第三方预览地址或以内联 HTML 展示上传内容。
- 在该文件的版本管理内“上传新版本”，上传完成后列表与资产当前大小、更新时间、用量一起刷新；失败保留原选中版并可重试。恢复旧版后更新当前标记、资产行和用量；弹窗关闭/项目切换、被撤权、晚到响应都不能显示旧项目版本。新版本按钮在归档项目不可用，服务端仍独立拒绝。
- 旧版下载必须使用当前登录请求获取 Blob，不缓存跨用户复用的下载 URL。成员被撤权后的旧版下载入口应消失；即使界面来不及刷新，服务端 404 仍为最终边界。没有安全预览的版次不能用“预览”伪装真实能力。

## 失败优先验收

先写失败的仓库、路由和前端测试，再实现。至少覆盖：023A 单版升级无需数据迁移；上传第二版后新旧字节、摘要和当前标记；恢复第一版再恢复第二版；重复恢复幂等；两个连接交错上传/恢复后恰一当前版；上传在磁盘发布前、发布后 DB 提交前和提交后响应前故障；成员在列版本/下载/上传/恢复期间被移除；外人、跨项目 ID、同项目跨节点 `version_id` 的恢复与历史下载、目录、归档、对象缺失、超限；版本分页同秒时间固定数据集下稳定；旧版链接撤权 404；响应及日志不含对象键、路径和凭据。SQLite 新库和 023→当前库升级都测；PostgreSQL 真实迁移与并发测试在可用环境运行，否则明确未验。

Codex 只整合白名单差异并独立复测，GLM 只读挑战 SQL 锁序、撤权与崩溃窗，三身份登录浏览器覆盖新增/恢复/旧版下载及刷新，最后再快进推送用户远端。通过本片只可核销“项目资产版本核心旅程”，不得核销 PS-06B 整体或 WorkBuddy 1:1。
