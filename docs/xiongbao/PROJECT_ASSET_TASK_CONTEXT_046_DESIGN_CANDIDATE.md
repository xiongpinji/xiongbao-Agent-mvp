## 引用、版本与文件夹

- 草稿引用仅在当前页面内存中保存，按 project ID 隔离；导航到其他项目、退组或认证失败后清空。不保存到 localStorage，不包含 object key、绝对路径、访问令牌或可重放下载 URL。
- 每张 UI 卡片有独立草稿 ID，允许同一资产重复出现并分别移除，沿用已观察的交互。提交时，底层按 `(node_id,version_id)` 去重读取；保存卡片到唯一文件的映射，避免重复解析和重复计费。
- 文件以提交前确认的当前版固定为 `version_id`；新版本上传或恢复不会改变既有任务引用。后续改名/同项目移动不改变 ID 和字节；新任务重新取当前版。第一版不提供“跟随最新版”。
- 文件夹在确认提交时递归展开活文件，固定成员清单及每个文件的版本，不自动包含以后新增的文件。嵌套目录、重叠文件夹与直接文件引用需去重。回收站节点及其后代不进入清单。
- 提案边界为 20 张草稿卡片、50 个唯一文件、目录深度 16、单个引用文件 20 MiB、唯一文件合计 100 MiB。超限、空文件夹或任一无权项使整体预检失败，不静默截断或跳过；卡片显示可处理的具体错误，草稿保留。这些是读取限额，不修改现有资产上传上限、项目容量或 WorkBuddy 账号配额。
- 预检展示文件数量、总字节及支持状态；只允许本地解析的 `.txt/.md/.csv/.pdf/.docx/.xlsx/.pptx`。图片视觉、OCR、音视频、网页链接、外部来源及大规模 RAG 属后继片，不调用付费解析服务。不能把“可上传资产”误作“模型已能理解该格式”。

## 授权与隔离

任务默认本人私密。预检、创建、每轮执行前和每次工具读取，都根据服务端身份重新核对项目成员、本人任务、专家可用性、活节点及同节点版本归属。非成员、撤权、跨项目、陌生任务和未知引用统一 404；项目归档后拒绝新建资料任务，已有任务的新增执行同样拒绝，原已授权历史读取沿既有合同。

固定版本不冻结授权。节点进入回收站后拒绝新的读取；按 042 恢复后，只有当前成员和原固定版本仍有效时才允许再读。同项目移动和改名不扩大授权。脱离项目的旧任务关联不能继续调用资源通道；源专家禁用、取消共享或任务删除也拒绝新的执行。每项读取采用当前 ACL 和版本关联，不能仅信任预检 ticket 或客户端缓存。

026 项目指令快照、046 资源版本清单和模型当时已接收的文本是不同数据。撤权能阻止后续读取，不能追回已经交给模型的内容、已生成的回答或用户已经下载的字节。025 显式文本分享可能包含助手引用过的资料内容；这仍由任务所有者明确授权，不自动授予资源 API、工具、原文件、stream 或写权限。卡片摘要和项目动态不增加引用名称、原文、私有路径或下载链接。

运行时资源工具只接收任务内不透明的 `resource_id` 和有界文本分页，不接收客户端/模型传来的路径、URL、object key、用户 ID 或项目 ID。调用者、task 和 project 由当前服务端执行上下文绑定。文件名和文件正文均是非可信资料，不作为系统指令或工具授权。任何共享 Agent 上的全局工具列表、闭包、可变上下文和跨线程解析缓存都不能代替任务隔离。

## M0 必须回答的能力问题

M0 是批准后的有界探针，不是生产功能开关：使用合成资产和假模型，至少两用户、两任务以及同一共享专家并发执行；不改真实凭据、不调用付费模型。

1. 资源工具和所有普通工具是否能使用不可伪造的当前 user/thread 上下文；该上下文是否覆盖 WebSocket、HTTP、恢复/重试及内部 enqueue 入口。
2. 资源正文、解析临时文件、历史及工具缓存是否会落入另一用户能读的 Agent 工作区、共享 memory namespace 或日志；若不能隔离，推荐方案 NO-GO。
3. `manager.py`、gateway process 与 harness 的工具接缝是否支持每任务绑定而不热改共享 Agent；同时保留普通任务旧行为且不打开 030 文件模式。
4. POSIX/Windows 资产存储的授权读取句柄能否安全交给解析器。现有 `parse_document(Path)` 按后缀选择格式，私有对象名无扩展名，不能直接拼接文件名或给解析器原物理路径。
5. 首轮持久化、实际入队和断线恢复能否区分“未发出、已发出、结果未知”，并阻止未知状态下重复提交产生第二次模型执行。

每个问题输出来源定位、可失败测试及实际结果。探针通过后才能固定 runtime kind、完整工具清单和迁移；本候选不预先宣称现有 harness 已支持上述能力。

## 服务与数据合同草案

建议增加独立资源 repo/service，HTTP 层只做校验与错误映射。SQLite/PG 成对迁移；编号在实施前按实际最高水位串行分配，不重建既有任务、资产或版本表。

| 对象         | 保存内容与约束                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------ |
| 预检记录     | 归属当前 user/project、原卡片顺序、唯一文件版本清单、摘要和 5 分钟到期时间；不保存提取正文，不作后续读取凭证       |
| 任务资源清单 | 同项目任务及所有者、卡片映射、唯一 node/version 引用、当时安全显示名/大小/摘要；复合 FK 保证同项目、同节点版本关系 |
| 首轮提交记录 | user/project/request ID、精确请求摘要、唯一 thread 绑定、阶段及结果；不在项目动态或普通日志写正文                  |

建议接口为 `POST /projects/{id}/task-resource-preflights`、`POST /projects/{id}/tasks/resource-start` 和本人任务的 `GET .../tasks/{thread}/resources`。前两个请求严格拒绝额外字段；预检返回不透明 ticket、安全清单和限额，创建接收 ticket、专家、已确认指令/专家修订号、任务文本及客户端 request ID。不会接受任意下载地址或指定 actor/source。

创建必须在一个授权事务内重新验证预检、重新展开选中目录并比较摘要、保存私密任务与完整资源关联；任一资产、目录成员、版本、指令或专家改变返回明确 409，事务无新任务。重取并由用户确认后才能提交；不能自动把变化后的资料当作原选择。预检的读取快照只证明那一次展示，不能替代创建时的重新验证。

并发实现沿现有资产仓储的 member-row → structural-root/node 锁顺序，不能另造 project-first 锁与之死锁。PG 文件夹展开还必须防止新增/移入 phantom，版本固定须与上传/恢复串行；所有相关创建、上传、移动、回收、恢复入口的锁协议要在 M0/R1 核对并用双连接交错测试证明，单条 `SELECT` 或普通读取快照不是这项证明。

同 request ID、同输入重放返回同一 thread 和当前阶段；不同输入 409。持久化成功后才入队，执行器通过唯一首轮 claim 防止重复消费。崩溃、断线或已入队但未见确认时返回结果未知并查询原提交状态，不自动发第二轮或另建任务。停止中/未知状态的恢复需显式操作；不能声称跨供应商端到端 exactly-once。创建与首轮是两个阶段，未实际发出不显示“任务完成”。

## 解析与模型读取

授权服务通过现有受控存储打开固定版本并校验大小/摘要；用受限解析适配选择格式。优先句柄/字节解析，确需临时文件时只能写到本任务独占的服务临时目录，禁止跟随链接，不进入 Agent 通用工作区；正常、失败、取消均清理 owned 临时对象。解析子进程限制 512 MiB、15 秒和 Office ZIP 解压总量 100 MiB，不执行宏、脚本、远程关系、OCR 或外部 fetch。超限和解析失败是资源错误，不返回伪成功正文。

单文件最多提取 1 MiB UTF-8 文本；工具每次最多返回 12,000 字符，返回当前 offset、下一 offset、总量及明确截断标记。模型读取的是工具返回的有来源文本，元数据卡片不是已读证据。长文件分页、坏文件和空/扫描 PDF 有明确结果，不能把空文本解释成已经读懂。解析缓存仅在本轮授权后按 task/node/version 隔离使用，任何正文返回前再次检查当前权限；中途撤权后不继续返回新页。已经交付的页仍适用上文不可追回的限制。

## 前端与验收

项目四页签沿用底部输入框、资产行内按钮及选择弹窗；卡片、选择器、确认清单、冲突和提交状态均有中文/英文、键盘、焦点和窄屏路径。页签切换保留同项目草稿，换项目及权限失败清空。资产操作只维护草稿，不隐式发送。创建失败保留文本和卡片；已创建/未知状态展示同一个任务的入口和状态，不通过再次点击创建重复任务。运行能力不满足时，显示真实原因并禁用发送，不能通过 UI 打开门禁。

验收分开记录：组件/单元、SQLite/PG 双连接事务、真实 TCP API、登录后的多身份浏览器、假模型实际收到的资源文本、Windows 存储探针、WorkBuddy 同夹具交互/视觉、真实供应商结果。只有引用卡片和新任务 ID 不足以通过 R3。固定版本、文件夹冻结、重复去重、旧 ticket、撤权/回收、共享摘要/文本边界、解析限额、首轮重放/未知结果及并发任务隔离均须先 RED 后 GREEN。付费供应商和用户账号验收另行取得具体对象与成本授权。
