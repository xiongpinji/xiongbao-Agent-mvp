# 046 项目资产「添加到任务」实机观察

2026-09-28，在用户已打开的 WorkBuddy 5.6.2 Windows 客户端中，只读检查既有项目的「资产」页。文件行悬停时，文件名右侧出现「添加到任务」按钮；点击后，该文件以可移除的引用卡片进入项目页底部的任务输入框。点击卡片上的移除控件后，输入框恢复为空。没有发送任务、创建待办、上传文件或修改资产。

随后点击「系统文件」文件夹行的「添加到任务」，文件夹同样以可移除的引用卡片进入项目页底部输入框；移除后输入框恢复为空。没有发送任务、展开文件夹内容或修改资产。

同一 PDF 文件连续点击两次「添加到任务」会在输入框中出现两个同名引用卡片，两个卡片均可分别移除；本次已全部移除。这只说明 UI 未去重，不代表提交后会处理两次文件内容。

这些操作证实**文件或文件夹 → 项目任务输入框中的待发送引用**这一 UI 入口。它不证明 WorkBuddy 如何传输文件字节、任务创建时保存哪个版本、文件夹会包含哪些后续文件、任务成员是否能读取原资产，亦不证明它把资产链接到「计划」页待办。文件右键菜单本次显示移动、重命名、下载、版本管理和删除；「添加到任务」在行内独立按钮。

熊宝的后续设计应将三个概念分开：项目资产自身的成员授权、输入框内尚未发送的临时引用，以及提交任务后持久化的资源关联。提交和后续读取都必须重新核对项目成员、资产活动状态与任务可见性；持有旧节点 ID 或旧输入框卡片不得扩权。具体版本固定、撤权语义和失败反馈需要单独设计并验收，不能由本次 UI 观察推定。
