# 043 项目资产文件行预览设计

状态：按用户已批准的 WorkBuddy 项目空间对标目标制作的受控实施片；尚未验收，不核销 PS-06 或视觉 1:1。

## 观察与边界

WorkBuddy 5.6.2 实机：点击既有 PDF 文件行，在项目页右侧打开可关闭的预览层；顶栏显示文件名、时间及操作入口，PDF 区有页码、目录和缩放等控制。熊宝当前文件行只提供下载和版本管理；已有 027 历史 PDF 预览只挂在版本弹窗。第一片补“文件行 → 当前版预览层”，仍保留版本弹窗与原下载行为。移动、重命名、添加到任务、Office 预览和缩略图/反色等未实现的能力继续留在后续任务，不以假按钮冒充完成。

## 方案

采用现有项目资产 **当前版下载** API 获取字节，再复用 `ProjectAssetPdfPreview` 的本地 PDF.js 预览链。另一方案是先列版本再选 `is_current` 的版本 ID；恢复旧版后，当前版可能不在第一页，这会误显版本或要求遍历全部版本，因此不采用。当前下载调用增加可选 `RequestInit` 和进度回调，保留原有双参数调用兼容性；027 组件的版本选择改为必填的 `string | null`，`null` 明确表示当前版，非空 ID 表示指定历史版。组件继续验证元数据大小、实际 Blob 大小和 `%PDF-` 签名，取消/切换时中止请求，不创建公开 URL，不渲染上传的 HTML/SVG。

文件行名称成为独立可键盘激活的按钮，点击后打开右侧抽屉；下载及更多菜单仍是并列操作，互不误触。抽屉顶部显示安全文本文件名与服务端更新时间，提供放大/恢复、关闭及已有的下载、版本管理、移入回收站操作。非 PDF、空文件和超 25 MiB 文件可以打开抽屉，但显示“此类型暂不支持在线预览”及下载/版本入口，绝不请求预览字节。可预览性条件与版本弹窗一致：`.pdf` 后缀、`application/pdf`、`0 < size_bytes <= 25 MiB`；真实 Blob 仍独立校验。

抽屉状态绑定 `projectId + node_id`。项目切换、失去授权的 404、关闭抽屉或文件被移入回收站时清除旧状态；晚到结果不能回填新项目。404 先关闭预览并重新读取项目资产列表，区别缺失单个对象与成员撤权。抽屉内版本管理复用现有弹窗；删除复用 042 确认与软删除流程。所有资产名称作为 React 文本呈现。

## 验收

- PDF 文件行可通过鼠标和键盘打开当前版抽屉；调用当前版下载 API，不依赖首屏版本列表，版本弹窗仍下载指定历史版。
- 抽屉关闭/项目切换会中止或忽略晚到预览与 404；真实撤权重查后清空资产，缺失单个对象可恢复列表。
- 不合条件文件不发预览下载；伪造 PDF 签名/超限 Blob 不进入渲染器；回收站条目始终不能预览。
- 已有下载、版本、软删除路径可用；抽屉与菜单不把未实现能力显示成已可执行。
- 前端定向测试、类型检查、格式/静态检查和生产构建通过，再做登录态浏览器/视觉对照；GLM 固定字节只读审查后才可归入验收。
