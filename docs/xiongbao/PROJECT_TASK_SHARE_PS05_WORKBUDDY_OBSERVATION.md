# PS-05 项目任务分享：WorkBuddy 本地任务实机观察

2026-09-28，在用户已打开的 WorkBuddy 5.6.2 Windows 客户端中，只读进入一个既有项目的「任务」页与其中一条已完成的**本地任务**。任务列表显示“你的任务是私密的，除非你共享它们”，并有范围、来源两个独立筛选。打开任务后，顶部面包屑保留「项目 / 项目名 / 任务名」和「本地」标记。

点击任务页顶部「分享任务」后，页面进入消息选择模式：可见逐条选择框、底部「全选」，以及「分享到微信 / 分享到朋友圈 / 复制链接 / 生成二维码 / 浏览器打开」五个动作。观察时可见消息处于选中状态；没有改变选择、复制链接、打开浏览器、生成二维码或调用任何外部分享渠道。随后点「退出分享」并返回项目任务列表，未更改原任务或分享权限。本文件不记录任务对话正文、附件名或用户账号信息。

这次操作只证明**本地任务的可选消息外部分享界面**存在。它没有证明链接的访问范围、有效期、撤销能力或接收方权限，也没有进入云端任务的项目成员协作、实时共同编辑或任务移交入口。项目成员资格与选中消息的外部分享不能合并为一个权限概念；熊宝现有任务卡片分享与对话文本授权须按各自合同单独对标，不能因顶部按钮外观相似就标记 PS-05 完成。

## 熊宝当前接线与差距

熊宝项目「任务」标签的所有者卡片在 `dashboard/src/pages/Projects/ProjectTasks.tsx` 中打开「分享任务卡片」弹窗：第一次只给指定项目成员授予卡片摘要；已有卡片接收者可再单独授予/撤销纯文本正文。接收者只进入项目内的只读摘要与受控正文视图，不取得所有者 `/chat` 深链。`src/octop/infra/db/repos/project_task_content.py` 读取正文时同时核对当前成员、有效卡片及独立文本授权，缺一返回 404；撤销卡片会删除对应文本授权。项目 owner/admin 身份不自动扩展到其他人的任务正文。

当前 `src/octop/infra/db/migrations/025_project_task_content_grants.sql` 的授权键为项目、任务和接收者，`dashboard/src/api/modules/projectTasks.ts` 的文本授权接口没有所选消息参数，所以这是受支持纯文本投影的**任务级**授权，不是 WorkBuddy 本次所见的逐条消息选择。当前 `dashboard/src/pages/Chat/index.tsx` 顶栏也没有同等「分享任务」入口；未找到微信、朋友圈、外部链接、二维码和浏览器打开的分享流程。这是代码静态核查，没有在本次运行熊宝的端到端测试。

与 [项目空间差距台账](PROJECT_SPACE_GAP_AUDIT.md) 的 PS-05 行配套使用。下一步需在 WorkBuddy 云端协作任务的安全可观察状态、以及熊宝多身份真实任务旅程中另行验证项目内共享与撤权；本次没有创建或发送任务。
