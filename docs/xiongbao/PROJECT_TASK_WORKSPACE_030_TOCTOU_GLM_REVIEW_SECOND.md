## 2. Findings

**P0: none. P1: none.**

### P2-1 — S4's tool-arg legality matrix omits bare-relative fragments, which the repo's own test proves are legitimate

- **Where:** design §2.1 P1 row ("工具 schema 要求单个前导 `/`"), §5.2 S4 (legal forms enumerated: one leading `/`, `/` alone, omitted optional path), §6.1 S4 ("未知形状 ⇒ 拒绝"), §6.3 A6 and §7.1 RD-4 positive-case lists (none include a bare-relative path) — vs. `tests/unit/agents/test_project_task_file_boundary.py:333-364`: `test_real_harness_graph_allows_allowlisted_forged_call` drives the **real harness graph** with `write_file` args `{"file_path": "forged-positive.txt"}` — **no leading `/`** — and asserts a non-error ToolMessage plus the file written at the root. This is the very test line the design cites as its `[DEP-TEST]` schema anchor (`:347`).
- **Trigger:** an implementer writing `_path_veto` from the enumerated legal forms plus the fail-closed unknown-shape rule rejects bare-relative calls. The existing green test goes RED (caught, but the design then needs revision anyway), and in production every model call that naturally uses a relative path (`write_file("notes.txt")`) returns an error ToolMessage — the same "rejects legitimate tool calls" defect class this amendment was repairing. The alternative failure mode — silently accepting bare-relative without any pinned test — leaves the acceptance decision at a security veto seam unpinned.
- **Impact:** no direct escape (converted fragments still pass S1/S2/S3), but the design's positive contract is incomplete relative to the installed stack's demonstrated behavior, and its schema claim ("requires single leading `/`") is contradicted by repo test evidence at its own citation. The `[CODEX-DEP]` "requires" reading is presumably description-level, not enforced validation — I could not read the installed source to confirm.
- **Minimal repair:** in S4/A6/RD-4, classify bare-relative fragments explicitly — recommended: accept, treat as a root-relative fragment, then run S1/S2 (+S3); add RD-4 positive cases for single-leading-`/`, bare-relative, `glob/grep.path=None`, and root-anchored patterns, and a negative case (`..` in the relative form); soften §2.1/§3.2 to "单前导 `/` 与裸相对片段均为已观察的合法形态（以 IT-1 在真实构造工具上钉住强制语义）".

### P2-2 — S1/S5/S6 do not enumerate the managed ancestor chain; a persistent junction at `~/.octop` (layout root) is unspecified and untested

- **Where:** design §5.2 S1 ("先 `lstat` 验证托管根本身及其**受管父目录**" — singular, ambiguous between one level and the full managed chain), §5.2 S5 (same phrase), §6.1 seams, §6.3 (A15 covers only the runtime root itself) — vs. verified code: the resolver receives the **unresolved** layout path (`api/common/workspace.py:165-183` → `paths.project_task_file_runtime_dir` → `PathLayout.from_env()` = `Path.home()/".octop"` or `OCTOP_HOME`, unresolved, `infra/utils/paths.py:38-46, 100-110`), and `Path.resolve()`/lstat traversal follows intermediate reparse points.
- **Trigger:** P4 (same OS account — explicitly including ordinary shell-enabled agents' subprocesses per §2.1) or P5 on a loose-ACL shared `~/.octop` (the exact scenario §2.1 P5 contemplates: "P5 可能获得植入能力") plants a persistent junction at `~/.octop` while `<agent_id>` and `project-task-files` remain real directories (replicated under the junction target). `lstat(root)` and `lstat(project-task-files)` traverse the `.octop` junction and report plain directories; `root.resolve()` and target both resolve into the attacker-chosen tree, so containment passes. Every current layer and the root+immediate-parent walk as literally specced passes.
- **Impact:** a persistent-plant class — the class B+ exists to deterministically refuse, under exactly the broken-deployment premise the design itself states (§2.1 关键推论 (i)) — escapes the specced check chain; §2.2 C3's wording ("任一字面组件") over-promises relative to the enumerated chain; the acceptance table makes the ancestor level unfalsifiable.
- **Minimal repair:** enumerate the no-follow verification chain precisely in S1/S5/S6 — every managed component from the layout root down (`OCTOP_HOME`/`~/.octop`, `project-task-files`, `<agent_id>`), each lstat'd no-follow per operation (bounded: 3 components, both surfaces); extend A15 or add A16 for a managed-ancestor junction replacement while running → refused on both surfaces, zero outside bytes; mirror in RD-2/RD-4. (If Codex instead chooses to narrow C3's claim and declare the ancestor level residual, that must be written as an explicit N-item — but given the P5 row already names this plant, enumerating is the consistent repair.)

### P3 findings (pin during the P2 repairs; none change the strategy)

1. **Plain-directory identity (rename) swap is outside every check.** S1's plainness proof cannot distinguish two real directories; a dir↔dir rename swap of the runtime root or managed parent redirects all I/O with zero refusals. Not claimed by C3 (reparse-only) and P4 gains nothing, but the broken-deployment rationale applies. Cheap deterministic hardener: record `(st_dev, st_ino)` of the S5-verified root and compare per-op in S1 — the repo precedent already does identity comparison (`asset_storage.py:151-183`); at minimum document the residual.
2. **S4 pattern-field traversal semantics are vague** ("与虚拟路径语义相符的模式/遍历检查"). Pin: standalone `..` segments in `glob.pattern`/`grep.glob` are rejected, patterns never enter the file-path normalizer. (HTTP-side patterns already go through the strict resolver at `routers/workspace.py:583-585`, which rejects `..` — the tool side needs the same rule spelled out.)
3. **`st_reparse_tag != 0` fails closed on non-junction tags** (cloud placeholders, dedup): availability-only false refusals if `~/.octop` lives under synced storage. Correct direction; worth one sentence next to N5 so operators can diagnose it.
4. **A13's 50 000-entry cap is not cheaply testable** as a fixed constant; make the cap an injectable parameter so RD-1 can test the boundary deterministically with a small fixture.
5. **Parent-directory mode:** §2.1 P5 now states the umask-created parent is enumerable, but the optional parent-chmod hardener from the first review remains undecided — fold it into S5 as an explicit decision point (or explicitly decline).
