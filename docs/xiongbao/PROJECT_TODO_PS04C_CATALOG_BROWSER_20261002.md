## 已验证的行为

| 场景 | 来源 | 实际浏览器结果 |
| --- | --- | --- |
| 目录 HTTP 500，正文含 `upstream not found` | 明确标记的浏览器受控响应 | 弹窗、标题、描述、截止日期保留；日期和创建禁用；不触发额外父项目确认 |
| 目录 HTTP 422，错误 code 为 `NOT_FOUND` | 明确标记的浏览器受控响应 | 同上；错误正文没有被当作项目失权 |
| 目录 HTTP 503，正文含 `upstream returned 404` | 明确标记的浏览器受控响应 | 同上；实际 HTTP 状态优先于正文 |
| owner 移除当前 member 后读取目录与父项目 | 实际本地 API：DELETE 204、目录 GET 404、父项目 GET 404 | 编辑器和计划内容关闭；项目名、种子标题、已保存标题、新草稿标题/描述/日期从文本、HTML 和输入值中清除 |

每个病例首先通过真实 DOM 填写不同草稿，并仅对一次创建 POST 返回受控 `422 VALIDATION_ERROR/details.reason=invalid_dates`。这四次日期失败是测试刺激，不是后端自然产生的 422。三个目录故障也均为受控浏览器响应；最终撤权、目录 404 和父项目 404 没有拦截或伪造。

前三例恢复时都取得实际目录 200；刷新本身不解除创建禁用，必须明确点击“确认比较”。第一例再实际创建一次，取得 POST 201、version=1，保存行与输入一致；待办和对应事件各增加一条，其它 Plan 数据不变。另两例取消，没有写入。撤权前后完整八组项目 Plan/待办数据相同，Root 在服务关闭后再次只读读回并核对一致。
