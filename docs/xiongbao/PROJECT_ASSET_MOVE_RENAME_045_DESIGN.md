# 045 项目资产移动与重命名设计（已批准方案）

2026-09-27。用户同意以单个原子更新接口实现移动/重命名，并冻结回收项删除时的原位置。此片补 PS-06 的项目资产行操作；WorkBuddy 5.6.2 实机只读观察到既有文件的“移动到 / 重命名”菜单，尚未执行两项操作，因此弹窗细节、权限和回收行为均为熊宝自己的合同，不宣称与 WorkBuddy 内部实现相同。依赖 023A 资产树、026 版本、042 回收站；043 当前版预览与本片前端都修改资产页，须顺序整合。

## 用户行为与边界

- 文件及文件夹的行菜单提供“移动到”“重命名”，沿用现有资产页的深色弹窗、按钮和反馈风格。重命名预填当前名并实时提示空名/非法名/同名错误；移动弹窗展示同项目活动文件夹树与项目根，当前文件夹及其后代不能作为目录的目标。文件夹选择器通过现有 `kind=folder` 列表逐层懒加载，按 `limit/offset` 翻到 `has_more=false`，不能只展示每层前 100 项；切项目/撤权时取消或丢弃旧请求。文件不显示自己的后代限制。打开弹窗不修改数据；确认期间禁用重复提交；失败保留原行、输入与弹窗，成功刷新当前目录并给出反馈。键盘可以进入、选择、确认和取消，Escape 只关闭最上层弹窗。
- 仅修改资产节点的显示名和父目录，不复制或重写私有对象、版本记录或当前版指针。`node_id`、所有 `version_id`、SHA、字节、`created_at` 保持不变；实际更改时更新节点 `updated_at`。同父同名含大小写折叠冲突返回 409，不覆盖目标。保持当前版本/历史版本下载的登录态授权。
- 第一片只支持同项目内单个节点及其整棵目录的元数据移动；不做跨项目复制、批量拖拽、目录深链、任务引用、产物回存或重命名历史版本。被回收的节点没有移动/重命名入口，也不能用旧 ID 调接口改变。当前文件夹中的远端协作者写入仍以刷新后服务器列表为准，不声称实时协同刷新。

## 身份、权限与树不变量

- 每次写操作在事务里先锁当前项目成员资格，再检查项目非归档和目标活动状态。非成员、撤权、未知项目、跨项目节点、已回收目标、隐藏根统一 404；当前成员无权管理返回 403，归档项目写入返回 403。owner/admin 可移动或重命名本项目任意活动节点。
- member 可修改自己创建的文件；修改文件夹时，目标及**所有后代（包括独立回收根及其后代）**的 `created_by` 都必须是本人，且每个独立回收根的 `deleted_by` 也必须是本人。空创建者/删除者仅 owner/admin 可处理。该规则严于 042 删除时的“活动后代”规则，因为移动或重命名祖先会改变已回收子项将来恢复的目录上下文。member 可以将自己可管理的节点移入同项目任意活动文件夹，和现有成员可在共享文件夹上传的权限一致；不要求目标文件夹由本人创建。
- 目标父目录必须是本项目活动文件夹；`parent_id:null` 表示隐藏根。跨项目/未知/已回收父目录返回 404，文件作为父目录返回 422。文件夹不能移入自己或任意后代，返回 `PROJECT_ASSET_INVALID` 422，且整笔事务无变化。禁止形成环；遍历父链时若发现既有环也 fail closed。目录下已有独立回收根仍沿其原父节点 ID 关联，未来恢复到该父节点**移动后的当前所在位置**。
- 名称继续使用 023A 的 `validate_asset_name`、NFC/trim/casefold 与设备名规则。服务端在锁内验证同父目标名称空位；数据库 `UNIQUE(project_id,parent_node_id,name_key)` 是并发最后防线。名字与父目录都未变化的请求返回当前安全节点，`updated_at` 不变；只更改大小写但 `name_key` 相同属于实际重命名，更新时间变化。

## API、事务与并发

`PATCH /api/projects/{project_id}/assets/{node_id}` 接收 `{ "name"?: string, "parent_id"?: string | null }`，至少显式提供一项。省略 `name` 保持原名；省略 `parent_id` 保持原父目录；显式 `null` 指向隐藏根。未知字段、空体、非法名字或父目录为错误类型返回 422。成功返回与现有列表相同的 `AssetNodeResponse`，只含安全元数据，不返回对象键、本机路径或回收元数据。客户端请求函数应保留 `null`，不能以空值合并把“移至根”误变成“保持原位”。

仓储在一个 SQLite `BEGIN IMMEDIATE` 或 PostgreSQL 事务内按“成员行 → 项目隐藏根行 → 目标及相关资产行”锁序执行。隐藏根行在结构更新中作为项目级序列化锁，令同项目两个并发移动无法各自通过旧父链检查而形成环；其后重新读取目标、目标父目录和其当前祖先链，检查权限、已回收状态、目录环与名称冲突，最后一次更新 `name/name_key/parent_node_id/updated_at`。**同一片必须把 042 `trash_node` 与 `restore_trashed` 改为成员锁后先锁隐藏根、再沿既有目标/后代或回收根/父目录顺序**：否则 restore 先持有回收根、move 先持有其活动祖先，彼此再等对方就会死锁。对 PostgreSQL 以 `FOR UPDATE` 锁隐藏根及其后相关资产行；上传/新版本等非结构写入沿既有单父/单文件锁序，不反向请求根锁。SQLite 根初始化仍在同一事务内幂等执行。任何校验或数据库唯一约束失败都回滚，名称冲突统一映射 409；实际 PG 并发用例验证锁序，无死锁或静默丢写。

前端文件夹选择树只帮助选择，不是授权依据；服务端对目标和父链完整重验。成功后当前目录列表、搜索/筛选结果、回收站列表及用量按需要重新请求；容量计数不应因纯元数据更改而变化。当前会话的面包屑若包含被更名/移动节点，则重置到项目根并重新加载，避免保留旧路径；切项目、撤权或晚到请求时丢弃旧项目结果，关闭相关弹窗。服务端不提供实时跨成员路径推送，用户手动刷新可从当前目录失效中返回根。

## 回收站“删除时位置”快照

042 的 `original_path` 当前按**读取回收站时的现有祖先链**拼接。045 开始允许更名/移动祖先后，这将误称新路径为“原位置”。配对的 SQLite/PostgreSQL v30 迁移在 `project_asset_nodes` 新增可空 `deleted_from_path`；升级时为现存独立回收根按升级当时的完整相对路径回填，遍历隐藏根以下的所有节点（含已回收祖先），不修改活动节点或版本。升级前尚无移动/重命名能力，因此此时可恢复它们真实的删除时路径。SQLite 迁移器的默认 `executescript` 不保证 DDL 与回填/版本水线原子性，故本片须新增 `_ensure_project_asset_move_rename_v30`：在 `db.transaction()` 中检查列是否存在、只补缺失列、回填所有未有快照的独立回收根，最后将 `_schema_version` 提到 30；中断重跑不得重复加列或留下标 v30 的半回填。PostgreSQL 使用现有事务迁移路径，另做两库 SQL 形状对照及真实 PG 回填测试。

此后回收操作在标记删除前，于同一事务计算目标的隐藏根相对路径并写入 `deleted_from_path`；同一回收树的普通后代保持空值，独立回收根保留自己原有快照。`list_trash.original_path` 从快照读取，前端标签改为“删除时位置”。恢复时仅清除本次恢复树的该快照，其他独立回收根不变。移/改祖先不改任何回收快照；恢复依旧按稳定 `parent_node_id` 回到原父节点的**当前**位置。若父目录仍在回收站或当前目录有同名活动项，沿用 042 的 409 且整树保持回收状态。界面说明这一区别，不能保证“恢复到删除时的文字路径”。
