## 问题与修复

当用户的新建草稿使用旧目录修订号，服务器先正确返回 `409 / catalog_revision_conflict`。用户点击刷新比较后，查询代次已经更新，但编辑草稿仍绑定旧 scope；稍后提交的真实列表回调误把它视为视图或筛选变化，清除比较就绪状态，导致「确认比较」消失。草稿保留却无法按原流程继续。

`dashboard/src/pages/Projects/ProjectPlan.tsx` 的修复只在当前用户、项目、视图及刷新结果校验全部通过后，把编辑 scope 绑定到已验证的新查询帧。旧目录修订号、待办版本、用户草稿和锁定状态保持到用户明确点击确认；没有自动重试写入，也没有放宽全局身份、视图或晚到回调守卫。

`dashboard/src/pages/Projects/ProjectPlan.test.tsx` 增加真实 Views/query hook 的回归，仅在新用例中控制 loaded callback 的交付时机：先显示比较确认，再交付刷新 Promise 完成后的新代次回调，检查完整草稿及创建禁用，最后明确确认并用新修订号创建。业务修复前有效 RED 为 **1 failed / 38 skipped**，失败点是晚回调后确认按钮消失；修复后独立 GREEN 为 **1 passed / 38 skipped**。较早的 selector 失败和一次未有效暴露竞态的 GREEN 尝试另行保留，不作为有效 RED。
