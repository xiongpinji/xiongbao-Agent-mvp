# 熊宝-Agent 项目空间差距与验收台账

更新：2026-09-24。台账覆盖 018/019 项目基座与 020 计划待办候选；推送版本以 `xiongpinji/xiongbao-Agent-mvp` 的 `main` 提交记录为准。本台账把**功能代码、自动化验证、真实多用户旅程、WorkBuddy 桌面视觉/交互对照**分开记录，避免把“页面出现”误判为“1:1 完成”。

## 对标证据与边界

- 用户本机 WorkBuddy 5.5.6 的只读观察，详见 [逐页记录](WORKBUDDY_LIVE_UI_AUDIT.md)：项目首页的搜索/模板/创建；项目详情“动态、计划、任务、资产”四页签；固定右侧项目配置；成员邀请；底部本地/云端任务入口。计划含表格与看板，任务页区分全部/个人/协同并提示默认私密，资产页有文件夹、上传、筛选和添加到任务。
- [WorkBuddy 官方更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog) 的 5.0.0 明确列出邀请与权限、计划看板、资产版本、动态、项目级配置、外部数据源/Webhook、实时协同/移交和消息中心；5.3.11 又增加邀请链接免审直接加入。更新日志是产品能力声明，不是熊宝已实现的证据。
- Octop 原始 `teams` 模块是 **Agent 专家团**，不是人的项目空间。当前熊宝用独立 `project_spaces`/`project_members`/`project_events` 及 `/api/projects` 建立了人的项目域；现有 `threads` 仍无项目关联或任务共享 ACL。加入项目**不等于**获得其他成员私密任务正文、本地文件或个人 OAuth 凭据的访问权。
- UI 目标是 WorkBuddy 同等信息层级、布局和交互路径，以用户提供的红黑金熊宝素材呈现；对标时不直接复用 WorkBuddy 商标和图片。

## 项目空间的关键授权链

| 资源 | 授权入口 | 必须拒绝的情况 |
| --- | --- | --- |
| 项目元数据、成员、计划和动态 | 服务端每次请求检查项目成员及角色 | 非成员枚举/深链/搜索、成员越权更改配置 |
| 项目内任务正文、消息、附件、执行流 | 独立任务拥有者/协作者 ACL | 仅凭项目成员身份读取私人任务、被撤权后继续读取历史/流 |
| 项目资产与旧版本 | 每个上传、列表、下载、索引引用检查项目 ACL | 猜测文件名、旧版 ID 或本地路径绕过权限 |
| 本地任务工作目录 | 后端规范化路径与执行器边界 | UI 选了目录但工具实际读写其它目录、符号链接逃逸 |
| 项目连接器与个人凭据 | 配置快照加用户/工具双重授权 | 加入项目即获得别人的 OAuth token 或未授权工具 |

上述是开发和验收边界，不把 `teams`、资料库或仅有按钮的 UI 代替对应资源。
