## 对标证据与边界

- 用户本机 WorkBuddy 5.5.6 的逐页只读观察及 2026-09-25 已更新至 5.6.2 的资产版本复核，详见 [逐页记录](WORKBUDDY_LIVE_UI_AUDIT.md)：项目首页的搜索/模板/创建；项目详情“动态、计划、任务、资产”四页签；固定右侧项目配置；成员邀请；底部本地/云端任务入口。计划含表格与看板，任务页区分全部/个人/协同并提示默认私密，资产页有文件夹、上传、筛选、文件右键操作和版本管理弹窗。版本恢复与多版本切换未实测。
- [WorkBuddy 官方更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog) 的 5.0.0 明确列出邀请与权限、计划看板、资产版本、动态、项目级配置、外部数据源/Webhook、实时协同/移交和消息中心；5.3.3 增加待办富文本编辑、评论图片粘贴上传与动态留言，5.3.11 又增加邀请链接免审直接加入。更新日志是产品能力声明，不是熊宝已实现的证据；富文本/评论/留言尚未在用户桌面窗口逐项操作验证。
- [腾讯云现行项目文档](https://cloud.tencent.com/document/product/1831/138797) 说明项目资料可进入任务上下文，任务产物可回存资产，文件展示更新人/时间，默认项目容量为 5 GB；它还区分项目公共授权与成员个人授权、本地/云端任务资源范围。上述是 WorkBuddy Enterprise 文档所述目标，不等于用户当前账号套餐能力，也不是熊宝 027 已实现的功能。用户实机所见的资产菜单、版本右栏与项目配置见上一条逐页记录。
- Octop 原始 `teams` 模块是 **Agent 专家团**，不是人的项目空间。当前熊宝用独立 `project_spaces`/`project_members`/`project_events` 及 `/api/projects` 建立了人的项目域；021 `project_task_links` 给本人任务登记项目归属，024/025 分别控制任务卡片与对话文本。加入项目**不等于**获得其他成员私密任务正文、本地文件或个人 OAuth 凭据的访问权。
- UI 目标是 WorkBuddy 同等信息层级、布局和交互路径，以用户提供的红黑金熊宝素材呈现；对标时不直接复用 WorkBuddy 商标和图片。

## 项目空间的关键授权链

| 资源 | 授权入口 | 必须拒绝的情况 |
| --- | --- | --- |
| 项目元数据、成员、计划和动态 | 服务端每次请求检查项目成员及角色 | 非成员枚举/深链/搜索、成员越权更改配置 |
| 项目内任务正文、消息、附件、执行流 | 独立任务拥有者/协作者 ACL | 仅凭项目成员身份读取私人任务、被撤权后继续读取历史/流 |
| 项目资产与旧版本 | 每个上传、列表、下载、索引引用检查项目 ACL | 猜测文件名、旧版 ID 或本地路径绕过权限 |
| 本地任务工作目录 | 后端规范化路径与执行器边界 | UI 选了目录但工具实际读写其它目录、符号链接逃逸 |
| 项目连接器与个人凭据 | 配置快照加用户/工具双重授权 | 加入项目即获得别人的 OAuth token 或未授权工具 |

上述是开发和验收边界，不把 `teams`、资料库或仅有按钮的 UI 代替对应资源。
