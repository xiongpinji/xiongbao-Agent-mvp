# 028 · 项目内新建私密任务与指令快照合同

状态：GLM 对初稿给出有条件 GO；Codex 核对既有锁序并纳入修订，现为实施冻结合同。此合同只覆盖 PS-05C/PS-07A 的第一片，不代表项目空间或 WorkBuddy 1:1 已完成。

## 用户可见结果

项目成员可在项目“任务”页选择自己有权使用的 Agent，预览并确认项目当前指令，再创建一个归属于该项目的私密对话并进入。项目右侧已有的“指令”由 owner/admin 编辑；新建任务冻结创建瞬间的项目指令。修改指令只影响后来创建的任务。任务卡片仍默认仅创建者可见，其他成员必须获得既有的显式卡片/文本授权。已有“关联对话”保持原语义，不倒灌项目指令。UI 必须明确本片仍使用所选 Agent 的现有工作空间；不能声称已提供隔离项目目录、云端执行、协同写入、任务移交、项目技能/连接器/定时任务。

本片的新建入口仅支持 `kind=expert` 的单专家 Agent。现有 `kind=team` 专家团会委派给 peer Agent，而 028 的项目指令快照只注入所选 Agent 的模型调用；若允许专家团，会误导用户以为每个受委派 Agent 都继承同一项目上下文。后端应拒绝专家团新建项目任务，前端选择器应过滤并说明该限制；专家团继承与跨 Agent 权限另立合同和验收。

## 服务端边界

- `GET /api/projects/{project_id}` 的成员可见详情增加当前指令的 `instructions_sha256`（对当前字符串的 UTF-8 字节作 SHA-256，不返回给项目列表）。新增 `POST /api/projects/{project_id}/tasks`，请求只含 `agent_id` 与 `expected_instructions_sha256`，操作者取认证用户。先走现有 Agent 访问检查；项目成员、未归档状态、Agent 身份和任务归属在写事务内复核。事务内重新计算指令摘要，与用户预览时得到的摘要不一致返回 409 `PROJECT_INSTRUCTIONS_CHANGED` 且无任何任务行，前端刷新详情后重新确认。未知项目/非成员同形 404；已归档项目拒绝创建；失败不得残留可见 thread/link/context。响应沿用私密任务安全摘要，不返回项目指令正文、个人授权、路径或 session key。Agent 允许当前用户按既有 ACL 使用的专家；共享专家不会因此获得项目成员或个人凭据权限。
- 新任务的 Dashboard DM thread、history projection、`project_task_links` (`source='project'`) 和指令快照在**同一连接的一次** SQLite/PostgreSQL 写事务内提交，不调用会自己提交的 `ThreadRepo.insert` 或 `ProjectTaskRepo.attach` 组合成伪原子操作。SQLite 用现有 `BEGIN IMMEDIATE` 写事务；PostgreSQL 按既有 `ProjectTaskRepo.attach`/`ProjectRepo.remove_member` 顺序先锁成员行 `FOR SHARE`，再锁项目行 `FOR SHARE`，然后插入四类行，避免与成员移除反向锁序。创建只插入 thread，不调用会重绑 active session 的 `ThreadRegistry.reset` 或现有聊天“新对话” HTTP 入口；后续进入 `/chat/{agent_id}/{thread_id}` 时沿用现有 `resolve_thread_id`/重绑行为。既有 `/links` 手动关联仍为 `source='manual'`，无快照。
- 通过新的成对 026 迁移保存每个项目新任务不可变的 `instructions_snapshot`、快照模式版本 `1`、`instructions_sha256` 及 `captured_at`，与 link/thread 级联。摘要是**已捕获的** UTF-8 原文哈希，不声称项目有单独递增内容版本；空指令捕获为空串且运行时不注入。快照只由服务端在同一创建事务中从项目行读取，客户端不能写；项目更新不会修改旧快照，旧快照是该任务后续运行的权威版本。快照正文不得写入项目动态、审计公开负载、HTTP 安全摘要或日志。项目删除、删除 link、移除任务 owner 的项目成员关系都须清除 link 和级联快照，原私密 thread 仍属于创建者。解绑后重新手动关联仅是 `source='manual'`，不恢复旧快照。
- 每轮执行在网关按 `thread_id + owner_user_id + agent_id` 查询仍有效的项目任务快照，放入服务端生成的独立 harness configurable key；绝不信任 WebSocket/HTTP/消息元数据中的项目 ID、指令、快照或同名 configurable，客户端值须丢弃而不是合并。只有 `source='project'` 且 link、成员、未归档项目、thread owner/agent 匹配时注入；旧手动关联、外人、退组、归档项目及普通聊天不注入。项目信息作为项目成员可编辑的工作上下文**追加在**既有 Agent system message 后；模型 middleware 每次从原始 base message 构造，若相同快照块已在末尾则不再追加，不能覆盖原指令、扩大工具/工作目录权限。同步/异步模型调用路径都须覆盖，重试不可累加重复指令。解绑/退组/归档与一轮进行中的竞态按“下一轮生效”验收，不声称能撤回已排入模型的上下文。
- 本片不将项目配置中的专家、技能、连接器或定时规则解释为自动工具授权。个人 OAuth 仍按当前执行者独立解析；项目指令由 owner/admin 撰写，可能影响执行者如何使用自己已经开放的个人工具，所以任务创建模态框必须显示**同一摘要对应的全文**并要求显式确认；若中途变更，409 强制重新预览。公共团队凭证与个人连接器的隔离、以及项目任务对个人连接器的进一步默认关闭/授权策略，须待独立配置/权限/撤销/审计合同。本片不声称阻止获授权用户的 Agent 遵从恶意项目指令使用其个人工具。项目任务继续使用所选 Agent 原有 workspace 和现有对话 ACL，项目成员身份不扩大文件/历史/WS 权限。

## 前端边界

- 项目任务页提供真实“新建项目任务”入口、可用 Agent 选择、当前项目指令全文/空指令提示、必须主动勾选的确认框、创建中/失败/无可用 Agent/项目撤权/归档状态；确认的摘要随创建请求发送。若摘要冲突，先刷新项目详情/摘要并要求重新确认，不直接重试旧摘要。成功后打开创建者 `/chat/{agent_id}/{thread_id}`。失败留在项目并可重试，不能生成假任务。已有手动关联、私密/共享卡片和只读文本路径保持不变。聊天页暂未显示单独“项目上下文有效/已撤销”标记，此观察性差距记录在验收中。
- 如项目页底部输入框在此片启用，只能以明确的“创建任务并前往对话”语义处理草稿；不得假装已把第一轮消息成功发送。可先保留底部输入为明确不可用，把真实创建入口放在任务页。任何草稿转移不得放入 URL、跨项目缓存或公开消息。
- 项目配置中除指令以外的行继续清楚显示未开放；指令显示和编辑应说明“仅新任务采用当前指令”。中英词条、窄屏和键盘路径须覆盖。

## 验收

1. 先写失败测试：三身份创建/列举/深链，归档、撤权、Agent ACL、摘要冲突与无副作用、跨项目/手动关联、事务回滚及迁移新库和 v25 升级；旧任务上下文不能被覆盖。
2. 网关和 middleware 测试证明合法首轮与后续轮都取相同快照，更新项目指令不改变旧任务；客户端伪造 metadata 不起作用；退组/解绑后不注入；原 system message 保留，模型重复调用不重复叠加。
3. Dashboard 定向组件与 API 测试、类型/lint/生产构建；Codex 独立跑后端定向、前端定向及三身份本地 API/浏览器旅程。最终固定 SHA 交 GLM 只读审查，修复 P0/P1 后推送并比对远端 SHA。
4. PostgreSQL 实库、安装后的桌面操作、WorkBuddy 全状态视觉与项目配置其他四项若未实测，继续标记未验或未实现，不能按本片关闭 PS-05C、PS-07A 或总目标。
