# 037 项目模板创建语义设计

状态：037 有界实现已通过固定提交审查；真实多用户项目旅程与 WorkBuddy 全量视觉验收仍待完成。2026-09-26。目标是在熊宝自有模板和项目 API 上，对齐 WorkBuddy 5.6.2 实机观察到的“选择模板后项目名称仍为空、确认不可用，指令已有预设”的创建语义。此片只改变创建表单，不新增项目资源授权。验收证据见 [037 验收记录](PROJECT_TEMPLATE_037_ACCEPTANCE.md)。

## 已有状态与选型

034 已把五个首页模板入口接到 `CreateProjectModal`。目前 `templateSnapshot` 会一起填入名称、描述和指令；弹窗内模板切换对脏草稿有覆盖确认。项目名在服务端仍须为 1–15 字。GLM 的 034 P2 指出：若弹窗保持开启而外部 `initialTemplateId` 程序化改变，当前 effect 会无确认重置草稿。实机参照还显示连接器/专家等可选资源，但熊宝尚无可安全复用的完整项目级授权合同。

考虑三种做法：继续自动填模板名只改提示，改动最少却无法符合实机“自己命名”；另外加命名确认向导可保留现有名字，但多一步且仍改变了实机路径；**推荐直接让模板只预填描述和指令，名称保持空白**。用户主动输入有效名称后才允许创建。熊宝模板内容保持原创，不拷贝 WorkBuddy 的预设文案或项目资料。

## 交互合同

从首页模板卡或弹窗内选模板，所选标记、描述和指令立即更新，项目名称始终清空；空名时创建按钮禁用。用户输入名称后可正常提交现有 `POST /projects`，服务端仍负责名称和成员授权校验。普通“新建项目”打开全空表单；编辑已有项目不应用模板，也不改变保存路径。模板选择不会自动创建项目。

草稿被用户修改后切换弹窗内模板，沿用现有覆盖确认：选择“保留”则名称、描述和指令逐字保持；选择“覆盖”才清空名称并应用新模板。弹窗已打开时若父级 `initialTemplateId` 意外变化，不得静默覆盖草稿；只在一次关闭→打开边沿应用该初始模板。关闭再从普通入口重开为空，关闭再从另一个模板入口重开只应用新模板。创建失败保留全部输入和选中状态。中文与英文仍用现有本地化模板键。

## 范围和验证

只修改项目创建弹窗及相关页面行为测试；首页布局 036 和项目详情 035 不属于本片。先写失败测试覆盖首页模板入弹窗的空名/禁用按钮、弹窗内切换的保留与覆盖、打开时父级种子改变、普通入口重开、编辑不变、创建失败保留输入，再实现。Codex 独立运行项目测试、类型/格式/构建及隔离浏览器，GLM 对固定提交只读审查；未完成审查和真实旅程前不核销 PS-01。

WorkBuddy 弹窗里的连接器、专家、技能等项目资源选择留给后续 PS-07：必须先定义项目配置、个人授权与团队凭证隔离、角色编辑及任务执行时的快照/撤权规则。037 不渲染看似可用的假资源控件，也不把模板选择当作这些能力已实现。
