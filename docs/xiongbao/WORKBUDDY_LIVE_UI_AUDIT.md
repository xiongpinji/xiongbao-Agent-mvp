## 项目空间专项观察

用户将 WorkBuddy 切到前台后，进一步只读打开了一个既有项目及“新建项目”表单。项目首页有五种模板和搜索；项目详情顶部依次为“动态、计划、任务、资产”，右侧固定“项目配置”包含指令、连接器、专家、技能、定时任务。页面底部的任务输入区可引用项目资产和待办，并可切换“本地任务 / 云端任务”。本地任务说明为可访问本地资源和项目共享资源；云端任务说明为可访问项目共享资源且可发起任务协作。由此可见，“项目空间”是共享协作域，“本地工作空间”是任务的文件执行域，两者需要分别建模与授权。

## 2026-09-24 项目宽窗口与事项详情复核

在用户已打开的 WorkBuddy 5.5.6 中，以 1280×768 窗口只读打开既有项目的“计划”页。表格和看板显示同一批事项；看板按状态分列并显示各列计数，卡片上有标题、状态、处理人和时间。点开既有卡片是覆盖项目页的双栏详情：左侧显示标题、富文本正文及底部评论入口，右侧依次是状态、处理人、开始日期、截止日期、优先级和标签。更多菜单提供“复制链接”“复制为指令”和“删除事项”，这里只观察了菜单，没有执行命令或修改事项。

表格视图默认露出标题、状态和处理人；其设置面板包含视图、字段显示、分组、筛选、排序、显示子待办和导入数据源。字段面板可选择状态、处理人、优先级、标签、附件、开始/截止日期、创建/更新时间与来源。这些是界面实见的验收目标，不能仅凭熊宝现有的三列布局和服务端筛选声称已经对齐；后续需验证表格/看板在字段与筛选变化后的数据一致性、持久性及键盘操作。

项目“任务”页有任务/来源筛选、标题搜索及“你的任务是私密的，除非你共享它们”的提示。打开既有项目任务后，任务页顶栏存在“分享任务”；点击后出现分享到微信、朋友圈、复制链接、生成二维码、浏览器打开的底部面板。没有复制或传播链接。计划事项的“复制链接”与对话任务的“分享任务”是两个不同入口；当前熊宝 024 合同只提供指定项目成员的**卡片摘要授权**，尚未复刻 WorkBuddy 对话分享面板、链接访问策略或正文协同，不能把 024 记为该完整旅程通过。

项目配置中的定时任务卡片在这个既有项目里显示计数，点“查看全部”可见两列定时任务列表、单次计划和启停开关；本次没有触碰开关或添加任务。以上观察只覆盖 UI 形态和已有数据的只读展示，不验证后端定时执行、分享链接访问权限或实际通知送达。

随后只读打开项目配置的“管理连接器”弹窗。弹窗明确分为“个人授权”和“公共授权”：个人授权页说明项目全员可用同一连接器选择，但**每位成员用自己的账号授权并以自己的身份操作**；现有连接器卡片包括 GitHub MCP、腾讯文档、乐享知识库、Notion、Supabase，其中未连接项显示“去连接”。公共授权页说明“添加团队凭证后，所有团队成员将使用同一凭证调用连接器”，当前该项目为空。没有点击“添加”或“去连接”，因此只确认 UI 与文案，未验证凭证创建、调用及撤权。熊宝 PS-07 的合同必须把项目选择、个人授权与团队凭证分成不同权限域；不能把个人 OAuth 令牌因项目成员资格而共享，也不能在未建团队凭证时暗示已有公共授权。

同一项目的“管理专家”打开居中的双栏卡片弹窗，顶部显示已添加数量和“添加”，底部保留“取消/确定”，现有专家卡片带头像、名称及一句描述。只查看了列表和布局，没有切换选择或保存。熊宝目前右栏专家卡仍是未开放提示，后续既要实现持久配置和运行时引用，也要核对这个选择/保存交互；单纯显示专家图标不算完成。

再次只读查看该项目的“任务”页，顶部任务范围下拉菜单明确是“全部任务 / 个人任务 / 协同任务”，旁边还有独立的“全部来源”筛选与标题搜索；页面同时提示任务默认私密，除非主动共享。熊宝当前 024 的 `own/shared/all` 是“我拥有的卡片 / 明确分享给我的卡片 / 两者并集”，其中 `shared` 不等于 WorkBuddy 的“协同任务”，且尚无同等来源筛选。因此即使 025 完成正文只读，也不能仅更换标签就核销 WorkBuddy 任务范围交互；PS-05C 需要独立协同任务模型和数据源分类后再对照。

## 2026-09-25 WorkBuddy 5.6.2 项目资产版本复核

本次继续使用用户已打开的桌面窗口。窗口内版本号已变为 5.6.2；此前 5.5.6 观察仍作为当时的界面快照，不能假定两个版本所有细节相同。1280×768 的项目页仍为四标签、右侧项目配置和底部任务输入区。任务标签的“全部任务”菜单现场确认含“全部任务 / 个人任务 / 协同任务”。资产标签显示新建文件夹、上传文件、容量、类型筛选、搜索和文件表格；表格字段为名称、类型、更新人、更新时间和大小。

[官方 5.6.2 更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog) 还列出项目本地任务进入准备状态过久的修复、连接器授权/关闭状态修复和文档预览窗口改进。因此熊宝后续项目任务验收要同时覆盖启动超时与可恢复错误态；项目连接器配置验收要证明撤销后工具确实不可用，不能只看右栏开关或图标。

对既有文件仅打开右键菜单，看到“添加到任务、移动到、重命名、下载、版本管理、删除”。选择“版本管理”后是覆盖项目内容的宽弹窗：左侧按版次和时间列出版本并标记当前版，右侧显示所选版的预览；本例只有第一版，因此没有可观察的恢复操作或多版本切换。当前预览由腾讯文档组件加载，这仅是 WorkBuddy 的实现观察，不构成熊宝上传文件到该服务的授权或设计要求。本轮未执行添加、移动、重命名、下载、删除、恢复、上传或任务启动。

PS-06B 至少要让版本列表、当前版标识、旧版成员授权下载、恢复后的当前版切换与刷新一致；若实现预览，须独立设计文件类型隔离和外部传输权限。右键菜单中的“添加到任务”还依赖 PS-05C 的任务级资源引用权限，不能仅显示按钮就算功能对齐。

## 2026-09-25 WorkBuddy 5.6.2 项目任务入口复核

继续只读操作同一个桌面项目页；本次窗口截图实测为 1273×634，与前述 1280×768 样本分开记录。逐一切到“动态 / 计划 / 任务 / 资产”，四个标签始终共用顶部项目面包屑、右侧项目配置和底部输入区；切换标签不改变正在选择的任务模式。动态页有“发布留言”“与我相关”“成员动态”，计划页提供表格、看板、新建视图、筛选、搜索、设置和添加，任务页提供范围与来源两个独立筛选、标题搜索及“你的任务是私密的，除非你共享它们”的提示，资产页仍有新建文件夹、上传、容量、类型筛选、搜索和文件表格。这是现行版本的入口与布局证据，不是写入、同步或权限能力证明。

在底部输入区打开“本地任务”菜单，现场看到两个选项：“本地任务——可访问本地资源和项目共享资源”与“云端任务——可访问项目共享资源、可发起任务协作”，当前勾选本地。再打开“选择工作空间”菜单，看到搜索工作空间、“新建工作空间”（当前勾选）和“打开本地文件夹”。没有选择文件夹或发送任务。这里的“项目空间”“任务运行位置”“文件工作空间”是三个不同概念：项目空间负责成员与共享资源；任务模式决定本地或云端能力；工作空间决定本地任务的文件范围。熊宝 030A 的系统托管受控文件任务即使通过，也只覆盖其中一小部分，不能把它标成 WorkBuddy 本地任务、云端协作或用户自选文件夹已对齐。

同一输入区的“默认权限”弹层说明操作会在安全沙箱范围内执行，超出范围会请求用户允许；另有关闭状态的“允许完全访问”开关。本轮只看了弹层，没有切换权限或发起执行，因此只记录界面语义，不推断 WorkBuddy 的实际沙箱强度。熊宝应将任务模式、工作空间范围和权限选择分成可独立验证的控制，不以一个 UI 开关代替服务端工具与路径拒绝。
