## 视觉约束与证据边界

- 当前固定观察窗口为 1280×768。WorkBuddy 使用低饱和深灰底色、左侧固定窄导航、中心弹性内容区；任务页右栏在展开后占约三分之一宽度。熊宝使用用户提供的红黑金素材，保留同等信息层级和交互路径，避免借用 WorkBuddy 的商标、图像或原样文案。
- 已只读打开既有任务、产物与图片预览；没有新建、发送、安装、授权、上传、分享或更改权限。项目卡片、连接器卡片和技能描述仅说明其 UI 与宣称能力，不是本项目的实现指令。
- 未观察发送后实时执行流、任务权限确认、编辑/归档/删除、真实连接器授权、定时执行、跨端续接或完整办公文件预览。上述能力继续保留“待真实用户旅程验收”。

## 项目空间专项观察

用户将 WorkBuddy 切到前台后，进一步只读打开了一个既有项目及“新建项目”表单。项目首页有五种模板和搜索；项目详情顶部依次为“动态、计划、任务、资产”，右侧固定“项目配置”包含指令、连接器、专家、技能、定时任务。页面底部的任务输入区可引用项目资产和待办，并可切换“本地任务 / 云端任务”。本地任务说明为可访问本地资源和项目共享资源；云端任务说明为可访问项目共享资源且可发起任务协作。由此可见，“项目空间”是共享协作域，“本地工作空间”是任务的文件执行域，两者需要分别建模与授权。

| 区域 | 只读观察 | 需要验证的行为 |
| --- | --- | --- |
| 动态 | 发布留言入口、“与我相关 / 成员动态”筛选、时间线。 | 成员操作与待办状态变更可追溯；无权者不可见。 |
| 计划 | 表格 / 看板切换、筛选、搜索、视图设置、添加；表格有标题、状态、处理人。 | 同一待办在两视图一致；状态与处理人改变后刷新可恢复；权限按角色执行。 |
| 任务 | 全部 / 个人 / 协同任务，手动 / 定时 / 本地来源筛选与搜索。页面提示任务默认私密，除非主动共享。 | 项目成员资格不自动授予私人任务正文访问权；协同任务须显式授权。 |
| 资产 | 新建文件夹、上传、类型筛选、搜索、容量、文件列表及“添加到任务”。 | 上传、引用、版本、下载及删除须验证成员权限，任务引用应保留来源。 |
| 邀请 | 成员列表、所有者角色、邀请入口、申请后加入的链接策略。 | 邀请、申请、审批、撤销和角色变更需服务端校验与审计。 |
| 新建项目 | 名称必填且表单提示最多 15 字；指令可选模板，连接器、专家、技能为可选配置。 | 创建后的配置刷新仍存在，且实际任务上下文只注入获授权能力；模板切换避免无意覆盖未保存输入。 |

没有创建项目、修改配置、发布留言、邀请成员、上传文件、读取私有资产内容或启动任务。邀请链接只在本机弹层观察，未传播。项目空间的完整协作与权限行为仍须通过熊宝的独立用户旅程验证。官方 [WorkBuddy 更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog) 的 5.0.0 说明也列出成员权限、计划、资产版本历史、动态、项目级配置和任务协同；它是对产品目标的官方说明，不代表熊宝已具备这些能力。
