# 熊宝-Agent 项目空间：WorkBuddy 5.5.6 对标规格

更新：2026-09-23。**项目空间是当前最高优先级。**本文是实施合同和验收基准，描述目标能力；除明确写作“Octop 已有”的部分外，均不代表熊宝当前已实现。桌面观察只记录控件和行为入口，官方更新日志用于核对目标范围，私人项目内容不进入本规格。

## 证据与产品边界

- WorkBuddy 5.5.6 实机只读观察见 [WORKBUDDY_LIVE_UI_AUDIT.md](WORKBUDDY_LIVE_UI_AUDIT.md)：项目列表、创建表单、动态、计划、任务、资产、右侧配置、成员邀请和项目底部输入区。项目任务分本地/云端；本地任务可用本地资源与项目共享资源，云端任务可用项目共享资源并发起任务协作。项目任务页明示个人任务默认私密，除非共享。
- WorkBuddy [官方更新日志](https://www.workbuddy.cn/docs/workbuddy/Changelog) 5.0.0 列出项目/邀请/权限、计划看板、资产库与版本、动态、项目级配置、实时协同与任务移交；5.6.2 仍在修复项目本地任务创建。官方文档描述的能力需在熊宝自身用真实用户旅程逐项验收。
- Octop `src/octop/api/routers/teams.py` 是**专家团**：成员是 Agent ID，不是人的项目成员。现有数据库最高迁移 017；`threads` 有 `agent_id/user_id`，无项目归属或共享任务 ACL。前端 `/workspace` 目前重定向到 `/experts`，无项目页。现有资料库/Agent 工作区/专家团均不能直接冒充项目空间。
- **项目空间 Project**：人的长期协作域，拥有成员、计划、资产、动态和项目级配置。**任务 Task**：对话/运行记录，归属用户与可选项目，默认仅任务拥有者可读写，显式协同后才扩权。**本地工作空间 Workspace**：任务实际文件和 shell 执行范围，由后端授权，不因加入项目自动变宽。**Agent/专家团**：执行主体/能力，不是项目成员。

## 用户旅程与行为验收

| 编号 | 旅程 | 验收条件 |
| --- | --- | --- |
| PS-01 | 项目列表与创建 | 用户能搜索、创建、打开自己有权限的项目；名称去空白后 1–15 字符且冲突/失败明确显示；刷新后仍在；非成员无法枚举。模板只预填草稿，切换有未保存内容保护。 |
| PS-02 | 成员邀请与角色 | 项目所有者可邀请、审批/撤销、调整角色；成员列表显示真实身份和角色；服务端拒绝非授权操作、自我踢出最后所有者及越权角色提升；撤权后旧页面与 API 立即失效。邀请链接使用不可猜测令牌、到期/撤销机制，不把链接作为匿名读权限。 |
| PS-03 | 动态 | 发布留言和成员操作、待办状态变化进入时间线；按“与我相关/成员动态”筛选，稳定分页；时间、操作者、对象和事件一致，不能通过动态泄漏私密任务正文。 |
| PS-04 | 计划 | 表格/看板展示同一套项目待办；新建、分配、状态流转、搜索、筛选与排序持久化；无权用户不能改；删除/退组后的处理人按明确规则处理。 |
| PS-05 | 项目任务 | 显示全部/个人/协同任务与来源筛选；新建任务带项目归属但默认仍私密；共享、协作、移交必须显式且可撤销；其他成员只能看到有权访问的元数据和正文，任务切换不得串上下文。 |
| PS-06 | 资产 | 文件夹、上传、类型/关键词筛选、容量、版本历史、下载/删除、添加到任务；同项目成员按角色读取，非成员无权；文件名、路径、索引引用、旧版本与下载接口均检查 ACL。项目资产与本地任务工作目录隔离。 |
| PS-07 | 项目配置 | 指令、专家、技能、连接器、定时任务可查看与按角色修改；任务创建时注入该项目当前获授权的配置快照。公共连接器能力和个人 OAuth 凭据分离，加入项目不共享个人凭据或扩大工具权限。 |
| PS-08 | 本地/云端任务 | 模式说明、可访问资源、协作能力与实际后端一致；本地任务的目录和 shell/文件权限由独立任务目录方案控制；云端任务不得借本机路径执行。后端不支持的模式在 UI 显示真实不可用原因，不产生假成功任务。 |
| PS-09 | 恢复与审计 | 跨浏览器刷新、并发编辑、撤销成员、项目归档/删除、失败重试和 403/404 均有一致结果；角色/资产/待办/协作/配置重要变更记录操作者、时间、对象和结果。 |

## 初版角色与授权表

WorkBuddy 实机仅确认了“所有者”和成员入口，以下是熊宝实施所需的**明确产品假设**，不是对 WorkBuddy 内部角色的断言：`owner` 唯一最终管理者，`admin` 管理项目和成员但不能移除最后所有者，`member` 可参与计划和项目资源；任务正文始终另走任务级 ACL。若未来观察到更细角色，在服务端扩展，不在前端本地猜测。

| 操作 | owner | admin | member | 非成员 |
| --- | --- | --- | --- | --- |
| 列表/读项目、读项目资产与计划 | 是 | 是 | 是 | 否 |
| 建项目、删/转所有权 | 自己创建/可管理 | 否 | 自己创建 | 自己创建 |
| 改项目指令/配置、审批成员 | 是 | 是 | 否 | 否 |
| 新建/改自己的待办、发布留言 | 是 | 是 | 是 | 否 |
| 更改他人待办/删除项目资产 | 是 | 是 | 待办处理人/上传者规则另定 | 否 |
| 读项目内任意任务正文 | **否，除非有任务级共享权** | 同左 | 同左 | 否 |
| 使用他人的个人连接器凭据 | 否 | 否 | 否 | 否 |

所有列表查询在 SQL/服务端按调用者过滤；详情、下载、历史、搜索、WebSocket、后台任务与深链都重复检查，不依赖前端隐藏按钮。其他成员无法通过项目 ID、任务 ID、资产路径或更改用户标识绕过。项目事件中仅放安全摘要，敏感指令和凭据不可出现在审计公开视图。是否允许成员删除自己上传的资产、是否提供项目级只读角色，在对应实施片前先定规则并写测试。

## 数据与接口合同

第一批采用迁移 `018_project_spaces.sql` 和 `.pg.sql`，两个数据库都要验证新库、017 升级及回滚失败后的重试。推荐稳定、不可猜测的文本 `project_id`；`project_spaces` 存名称、描述/指令、创建者与时间；`project_members` 以 `(project_id,user_id)` 唯一并记录角色与加入时间；`project_events` 记录动作、操作者、目标、时间及安全摘要。**第一批不改 `threads`，不假装已有任务协作**。后续 `project_todos`、`project_assets`/版本、`project_task_links`/`task_collaborators` 等分迁移加入，避免一次迁移跨越多个尚未验收的权限域。项目删除先软归档，实体清理与资产保留策略另验收。

第一批 API 契约：`GET /api/projects`（仅参与项目、搜索/分页）、`POST /api/projects`、`GET /api/projects/{id}`、`PATCH /api/projects/{id}`、`GET /api/projects/{id}/members`。响应包含真实 `my_role`、`member_count`、时间戳；创建在一个事务内写项目+owner 关系+事件。第二批提供成员邀请/审批与审计、计划；后续任务/资产/配置 API 分片完成。API 错误码遵循 Octop 统一错误封套，未授权详情宜返回 404 以免泄漏存在性；已登录成员但无编辑权返回 403。前端不得使用假项目数组或 `teamsApi`。

实施层级遵守根目录 `AGENTS.md`：`api/routers/projects.py` 只做 HTTP 验证与错误映射；`infra/projects/` 承担角色与业务规则；`infra/db/repos/projects.py` 只做 SQL；`RepoBundle/SharedServices` 接线；`api/app.py` 挂路由。React 通过 `dashboard/src/api/modules/projects.ts` 调用 `/api/projects`，`pages/Projects` 实现项目列表/详情，`routes` 和左栏接入口。项目 ID 路由参数、后端认证、选中态和错误态都要用测试覆盖。

## 分批实施与停门

1. **P0 基座**：项目创建/列表/详情/改名/说明，owner 成员关系与服务器 ACL，UI 列表、创建与项目详情四页签的真实数据空态。验收 PS-01 和“非成员不可枚举/访问”。没有真实数据源的页签明确标待建设，不能伪装成完成。
2. **P0 协作骨架**：成员邀请/审批/角色/撤权、动态事件和留言；计划待办及表格/看板。验收 PS-02/03/04；两个普通账户与一个非成员实测。
3. **P0 项目任务**：项目关联、默认私密、显式共享/协作/移交、来源筛选和项目配置注入。验收 PS-05/07，尤其历史/文件/WebSocket 全路径 ACL；任务目录安全另按 004 方案解决。
4. **P0 资产与模式**：项目资产文件夹、版本、任务引用、容量与本地/云端模式真实能力。验收 PS-06/08；不将 RAG 索引或 Agent 工作区包装成项目网盘。
5. **收口**：动态审计、并发/失败/撤权回归；同 1280×768 WorkBuddy 实机逐页视觉与交互对照；GLM 只读安全审查、Codex 独立跑测试和桌面用户旅程。未验证项继续在差距矩阵标差距。

并行所有权：Claude/Qwen3.8 Max 负责后端项目域、迁移、ACL 和测试；OpenCode/DeepSeek V4.1 Flash 负责隔离前端项目入口、列表、创建和详情 UI，按上述 API 合同接线；Qwen Code/GLM-5.3 只读复核角色、数据隔离及验收；Codex 写规格、整合共享文件、复测、提交与推送。首批前后端可在**不同工作树和互不重叠文件**同时做，测试与整合由 Codex 顺序执行；后续按真实 API 和权限验收推进。
