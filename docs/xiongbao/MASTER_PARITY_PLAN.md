# Goal

以腾讯云 Octop 为代码基线，把熊宝-Agent 的功能结果、桌面交互和用户可见品牌逐项对齐 WorkBuddy 5.5.6。交付可复现的真实任务证据、源码与测试、独立只读审查、差距矩阵及 Windows 桌面构建；每一批通过 Codex 验收后及时推送到用户指定的 `xiongpinji/xiongbao-Agent-mvp`。25 项矩阵见 [WORKBUDDY_PARITY.md](WORKBUDDY_PARITY.md)。

# Decisions and assumptions

- Codex 是总指挥，负责架构裁决、共享接线、独立验收、提交和推送。`claude-bailian/qwen3.8-max` 承担主实现；`opencode-bailian/bailian-token-plan-personal/deepseek-v4.1-flash` 承担可隔离的并行实现；`qwen-code-review/glm-5.3` 只读审查。所有任务只使用这三条已授权路由，不自动切换到其他模型。
- 以用户已启动的 WorkBuddy 5.5.6、官方任务栏/右栏/专家/连接器/自动化资料和用户的熊宝素材为验收参考。逐项记录“源码有、定向测试、浏览器可见、真实任务完成”四种不同证据；未走通不得标 1:1。
- 任务工作目录以实际后端授权边界为准；不能把 Agent 工作区 UI 或本地浏览器状态冒充任务级隔离。右栏“产物”只能来自当前会话，“工作空间文件”来自当前授权目录，“变更”必须有可复核的新增/修改/删除来源与 diff。
- 当前首版基线为 `1d64c5661968324fed4e44102b1690d54e16f321`。先完成共享的任务/结果闭环，再推进专家、连接器、资料库、自动化、跨端和安装；品牌与视觉回归随批次推进。
- 001 的独立审查经 Codex 源码复核后确认：Harness Agent 的 `workspace_dir` 和 backend `root_dir` 在 Agent 创建时固定，文件中间件不约束 shell；004 必须同时约束实际工具与文件 API，不能只做线程子目录或前端路径前缀。现有 `SessionList` 已有标题搜索及删除确认，但“加载全部”最多读取 50 条，精简导航没有搜索；005 只补真实缺口，置顶/重命名失败不能静默保持乐观成功态。
- 工作量与外部依赖尚不能精确预估。第三方账号授权、付费生产模型调用、部署与安装分发需要具体对象和成本证据；在得到相应授权前完成不依赖它们的代码、模拟链路和本地验证，并明确保留真实验收缺口。

# Constraints and guardrails

- 每个实施任务都用独立 Git worktree，明确文件白名单、最大变更数和验收测试；不同 worker 不同时写同一工作区。Agent Orchestrator 拥有顶层派工；worker 不创建子代理。
- 默认共享文件 `dashboard/src/pages/Chat/index.tsx`、`dashboard/src/pages/Chat/hooks/useSessions.ts`、`dashboard/src/pages/Chat/index.module.less`、`dashboard/src/locales/{zh,en}.json` 和跨模块 API 契约由 Codex 独占整合。若任务确需修改，先在该任务包中指定唯一文件所有者，等待并行任务结束后单独接线。
- Worker 不提交、不推送、不发布、不改凭据、不清理用户数据；不扩大授权路径。保持 MIT 许可证和上游归属，用户可见品牌用熊宝素材。遵守根目录 `AGENTS.md` 的分层和验证要求，禁止直接编辑 `src/octop/dashboard/` 构建产物。
- 先写可失败的行为测试，再实现。失败、取消、授权不足、空态、跨任务/Agent 隔离和重试必须覆盖；不能以按钮或静态页面替代可运行能力。已知全量前端套件未绿，单独跟踪根因，不掩盖。
- 对登录后桌面与 WorkBuddy 的视觉对照需真实可见页面和固定视窗截图；验证码不由自动化绕过。没有真实证据的能力保持待验收。

# Validation strategy

每项先做 RED 行为测试，再运行定向测试、类型检查和受影响模块的 lint。API/权限/持久化改动包含跨用户、跨任务、路径逃逸和失败重试测试；前端包含空态、错误态、键盘与移动端。Codex 独立重跑相关检查，按根目录 `AGENTS.md` 执行 `make all` 与 `make build-frontend`，检查 Windows CI 和 PWA/桌面构建。真实用户旅程用两个独立任务目录、增改删文件、真实办公文档和现有配置渠道；对 WorkBuddy 在同一视窗记录截图差异。单测、构建、真实 UI 和第三方服务验收分别报告。

# Completion criteria

25 项矩阵每行均有源码、测试、只读审查、真实用户旅程和视觉证据，或明确记录用户未授权/外部服务不可用的保留项；所有适用任务均由 Codex 接受并推送，远端 SHA 与本地一致、工作区无意外改动。不得把计划完成、worker 退出、CodeQL 通过或登录页截图等同于 WorkBuddy 全功能 1:1。
